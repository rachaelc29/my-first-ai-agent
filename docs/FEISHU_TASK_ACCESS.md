# 原生任务自动化的 API 访问诊断

2026-10-13：用户在独立 CRM-SYNC-TEST 表验证原生自动创建任务、任务ID回写及手机组件展示。原生动作列表未显示修改任务标题/日期的动作；第二个HTTP更新流程尚未启用，没有在流程中填写应用密钥或访问令牌。

使用测试应用 tenant_access_token 读取客户 C 关联任务返回 HTTP 403、数字错误码 1470403。官方[获取任务文档](https://open.feishu.cn/document/task-v2/task/get)明确将此码解释为“缺少对任务的访问权限”，区别于没有开启接口 scope。

官方[任务鉴权规则](https://open.feishu.cn/document/task-v2/task/overview)规定：创建人、负责人、关注人等可以读取；创建人、负责人及可编辑清单成员等可以编辑。应用 token 和用户 token 是不同身份；已经给应用添加接口读取权限，不会自动让它访问用户创建的全部任务。

下一步优先验证用户授权身份读取：测试应用增加 User token scopes 的 task:task:read，发布后建立一次安全用户授权。授权码、访问/刷新令牌不出现在聊天、代码或普通日志；令牌续期由服务处理，授权撤销/续期失败时暂停并请求重新授权。读取验证通过后才申请最少更新 scope 并做隔离任务写入测试。

用户授权接口必须只操作指定测试文件中已关联的虚构任务，不能因为用户有更广访问权就扫描个人任务。原生创建流程不删除，现存任务ID不清空，也不改负责人来试图绕过权限。

Mac本地只用于先期测试。要在Mac不开机时同步，仍需独立云端运行服务；尚未部署、未验证更新/回写、未启用任何收费服务。Cloud环境开发进程不等于生产运行服务。
