# 云端运行：费用、凭证保存和维护

日期：2026-10-13（墨尔本）。本文件用于选择方案，不部署、不扩大权限、不购买套餐。官方 Cloudflare/GitHub 定价文档访问被当前环境代理403拦截，以下预算不是已核实报价；部署前必须核实当时套餐、额度、地区、币种、税费及硬费用限制。

## 已有能力与仍缺少的服务

飞书原生自动化已实机验证：创建任务、把任务ID写回独立测试记录、显示在手机任务列表/组件，无需Mac开机。其菜单没有修改任务标题/日期的动作。用户身份读取及确认后的原任务更新已通过隔离测试。

目前更新仍靠本机临时程序，进程退出就丢弃令牌；没有云端部署、长期用户授权存储、刷新轮换、定时更新、原生任务完成回写或手机冲突确认入口。Apple路径的模拟/实机成功不能当作飞书任务云端同步验收。

## 方案与预算

| 方案 | 适合场景 | 规划预算（AUD/月） | 注意事项 |
| --- | --- | --- | --- |
| 仅飞书原生自动化 | 只需创建任务、不要求完整双向更新 | 可能无新增费用 | 飞书套餐和自动化执行额度仍需核实；不能满足已确定的全部更新/完成回写需求 |
| Cloudflare托管程序 + 必要持久化存储 | 不依赖Mac、少量分钟级核对与事件处理 | 免费试验目标0；正式轻量使用暂预留0–15，若额度不足需重新核价 | 不保证免费；计算、存储、调度、日志各自额度都要验证。常见Workers付费起步价曾为USD5/月，但未在线核实当前价格，也不保证含所有附加项 |
| GitHub Actions + 外部安全状态存储 | 接受较低频率和不保证准点的任务执行 | 公共仓库标准运行器可能0；私有仓库或超额费用需按分钟测算；外部存储另核 | 代码仓库可以保留GitHub；持久化状态不能放代码或普通构建产物；刷新令牌也不能靠每次启动重新授权 |
| Mac现有程序 | 先继续试用、不接受云托管 | 通常无新增托管费 | 需Mac可运行；开机恢复后重新启动，当前不满足Mac关机仍同步目标 |

预算假设为目前已知131+184=315条客户、每月新增约40条，但未确认同时活跃任务数。首批只验证少量虚构任务，不能按客户总数断言所有人都有跟进任务。初期只用明确日期规则，不调用AI/语音服务，所以不需要为同步额外支付模型费用。

免费标准主机运行器在公共仓库中的规则、私有仓库附带分钟数与超额单价以GitHub当前套餐为准。不能说GitHub Actions所有运行都免费。按30天、每次一个任务执行且耗时按整分钟计算：

| 周期 | 月启动次数 | 每次1分钟 | 每次2分钟 |
| --- | --- | --- | --- |
| 5分钟 | 8640 | 8640分钟 | 17280分钟 |
| 15分钟 | 2880 | 2880分钟 | 5760分钟 |
| 30分钟 | 1440 | 1440分钟 | 2880分钟 |

实际运行器计费规则仍需核实，这个表是用量估算，不是账单。若套餐包含2000分钟，30分钟轮询且每次1分钟才可能在其中；较短周期容易超出。scheduled Actions可以延迟，不承诺5分钟准点执行，也不是24小时进程。

推荐保留GitHub存代码、使用一个托管运行平台处理调度、OAuth回调和小量状态，避免把执行和状态分散到多个服务。Cloudflare是候选而非必选，免费方案是否可用需部署前核实。若用户更偏好Actions，也可采用，但必须单独安排安全状态存储。

自定义域名不是必须，可优先用平台提供的HTTPS地址。GitHub/Codex现有订阅费用与新增运行费分开，飞书套餐/原生自动化配额另核。不购买域名、不启用付费计划或填写付款信息直到费用明确且用户同意。

## 凭证与状态

账号应属于用户；启用双重验证，开发协作只授予必要权限。

静态应用密钥与状态加密密钥存托管平台Secrets功能，不放代码、URL、HTTP自动化明文框或普通环境变量；GitHub执行器如使用Secrets，也只供受控正式分支使用，不让外部PR运行有正式凭证的工作流。Secrets保护的是存放与分发，获授权运行代码仍能使用它，不能承诺即使代码或平台账号失陷也安全。

访问令牌及刷新令牌由一次官方浏览器登录授权取得。生产需要核实推荐OAuth端点、申请必要offline_access并处理刷新开关；本地历史v2探针不直接当生产实现。刷新令牌会轮换，必须安全、持久化并单线程刷新；失败/撤销/到期时暂停，通知用户重新授权，不伪装永久授权。

动态令牌加密后保存至受限云存储，加密密钥单独放Secrets；不存GitHub提交、缓存、artifact或普通日志。不要因为Actions Secrets能保存静态值，就假定它能可靠自动处理轮换令牌和同步事务。

同步状态仅保存必要的记录ID、任务ID、计划版本/基线指纹、操作结果和时间；如果失败恢复需要短期内容快照，必须加密、限定保留和访问。云端不建立客户档案或沟通历史库，飞书仍是唯一正式客户数据库。数据地区、跨境处理、平台条款和备份访问范围上线前核实。

日志只显示状态/脱敏错误与时间，不打印正文、录音、客户联系方式、授权回调查询参数、访问/刷新令牌或Secret。当前本机模拟预览不应扩展成生产客户日志。

## 维护责任与日常操作

用户无需每天开Codex或终端。首次授权后正常同步自动运行；真正双方冲突、授权撤销或不明确日期仍需用户确认。

用户需维护自己的账号访问，定期查看运行/费用概况，收到重新授权或冲突提示时处理。开发维护包括依赖/平台/API变化、安全修复、备份恢复演练和故障诊断；可由Codex继续协助，不能承诺永远免维护。

正式交付必须有定时运行健康检查、失败告警、最后成功同步时间、授权续期异常提示、暂停开关、可恢复的代码版本与加密状态备份。代码回滚不自动撤销已覆盖的飞书数据；正式写入前要确定客户表恢复措施。

月度查看费用和异常，系统变化时做小范围回归。不定期故障可能需要人工处理；不能用无限自动重试避免维护。平台预算告警不一定是硬上限，必须核实超额行为；不支持硬上限时停留免费方案或重新让用户选择可控成本方案。

## 交付与下一步门槛

先确认运行频率（建议试验5分钟而非实时）和预算上限，再核实选定平台的价格与套餐。先在虚构测试表部署验证更新、完成回写、去重、轮换、冲突及服务重启；完成后才准备正式表小范围上线。

尚未完成：托管平台选择与注册、OAuth长期保存/刷新、安全状态存储、云端执行器、冲突确认手机页面和费用实测。不存在可直接填写到HTTP请求中的现成服务URL。用户无需现在填写App Secret或提供平台密码。
