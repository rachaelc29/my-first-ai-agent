# Mac 同步程序：测试版运行指南

## 已交付与未验证

已交付可执行的 Python 同步引擎、模拟演示、Mac Swift/EventKit 连接源代码、独立飞书测试表连接器和本地配置工具。没有开发语音功能。

云环境是 Linux，没有 Swift/macOS SDK，因此 **Mac 桥接尚未编译或真机验收**。不能声称 Apple 连接、权限弹窗、iCloud 或飞书实际测试写入已通过。Mac 真机发现问题时继续修复，不绕过权限。

执行结果（2026-10-12）：

- `python3 -B -m unittest discover -s tests -v`：51 个测试方法通过，0 失败、0 跳过。其中 28 个同步测试、4 个测试表保护测试，以及此前 19 个字段读取/时间解析测试。
- `python3 -B -m crm_sync.main demo`：创建、Apple 改期/改内容、完成回写和再次运行去重均通过，只使用虚构内存数据。
- Python 语法、构建脚本 shell 语法及 Info.plist 格式检查通过。
- 未连接真实客户记录、未修改正式飞书权限或字段、未创建 Apple 待办、未部署付费服务。

## 程序行为

引擎先建立任务编号和持久化待执行状态，再执行远程变更。SQLite 保存双方基线及待执行快照。单侧变化自动同步；两侧冲突、身份异常、日期不明、空内容或完成版本无法核实时暂停。

测试阶段只允许一个本地进程，同时运行会被文件锁阻止。正常日志只显示状态，不显示客户文本和密钥。`--review` 是用户主动在自己的 Mac 上查看并确认测试内容，不是开发日志；不要把输出发到聊天或 GitHub。

Apple 编辑规则：任务标题和备注正文共同构成行动内容，底部 `[CRM_SYNC_TASK:…;CUSTOMER:…]` 是关联标记，不属于行动内容，不要修改。日期取提醒事项中的日历日期，暂不支持时间点、子任务或重复任务。

完成回写只采用可核实的最终内容，不生成 AI 总结。系统认为完成后发生过修改，或不能验证完成内容时，输出 `needs_confirmation`。本机可明确确认当前版本；这不声称恢复了完成瞬间的历史版本。

当前程序不删除任何提醒。旧计划已完成后如出现新计划，先暂停确认；`--review` 可选择 `new` 明确创建新轮次并保留旧任务。重新打开已完成任务暂未提供。

本地状态文件仅使用文件权限保护（目录 700、文件 600），未提供应用层数据库加密；建议 Mac 启用 FileVault。测试版只存虚构资料。没有备份恢复/密钥管理验收前不能用于正式客户。

## 分步操作顺序

实际指导一次只做一项。本指南列全流程用于理解，不要求一次执行全部步骤。

### A. 建立测试列表

在 Mac 提醒事项的 iCloud 分组新建一个普通列表，名字严格为 `CRM-SYNC-TEST`。不要建智能列表，也不要重命名现有个人列表。该名字必须唯一。

Mac/iPhone 若需共享测试任务，使用你自己的同一 Apple 账号、启用 iCloud 提醒事项；不向程序或聊天提供 Apple 账号密码。系统授权可能覆盖所有提醒事项，但程序只查询这个测试列表的任务；名单发现只显示这个列表的标识。

### B. 检查本机工具

需要 macOS、Python **3.10 或更高**（建议 3.12）和 Apple Command Line Tools。Mac 自带 Python 未必满足；没有工具时再单独指导安装，不默认需要 Xcode 完整应用。

在后续指导中检查 `sw_vers`、`python3 --version` 和 `xcrun --find swiftc`。Apple 提醒事项访问由本地授权控制，不把云端凭证复制过来。

### C. 下载与编译

从 GitHub 的 `followup-time-planning` 分支下载代码 ZIP，解压到你自己选择的目录。也可以使用 Git 克隆，但不要求没有经验的用户维护 Git。

在终端进入解压后的项目目录，运行：

```sh
bash mac/build.sh
```

这会使用本机 Swift 编译一个开发版桥接应用到：

`~/Library/Application Support/PropertyCRMSync/RemindersBridge.app`

使用本机 ad-hoc 签名，不使用付费开发者账号；不是已公证的分发应用。构建失败保留错误供诊断，不取消系统安全设置。构建本身不访问提醒事项。

### D. 配置模拟 Apple 测试

在同一项目目录：

```sh
python3 -B -m crm_sync.setup
```

首次可能出现提醒事项权限提示；确认应用与用途一致后授权。没有权限时暂停，不修改系统设置绕过授权。选择的测试列表在本地配置中保存，出现多个同名列表时拒绝设置。

配置文件位置：`~/Library/Application Support/PropertyCRMSync/test-config.json`。不在 GitHub 项目中，不包含 App Secret。设置步骤只查测试列表，不创建任务。

### E. 模拟客户 + 实际 Apple 提醒

```sh
python3 -B -m crm_sync.main mock-apple
```

默认虚构客户编号 `fictional-customer-001`，计划日期为墨尔本当天之后 3 天。虚构 CRM 状态保存在本地 `mock-apple/mock-crm.json`，可以用文本编辑器修改虚构计划；它不是正式客户数据库。

随后分次测试：重复运行不会重复创建；在 Apple 修改日期后再运行；修改标题/正文后再运行；完成任务后再运行。每次观察状态和本地虚构记录，不发送客户资料。

持续轮询模式：

```sh
python3 -B -m crm_sync.main mock-apple --watch
```

每 120 秒核对，按 Control+C 停止。是定时自动同步，不是零延迟实时。Mac 关机/睡眠暂停；恢复后重新运行命令补同步。当前尚未安装登录自动启动服务，不声称开机后自动启动。

有冲突时先停止 watch，再运行：

```sh
python3 -B -m crm_sync.main mock-apple --review
```

本机展示快照，选择 `crm`（以飞书模拟计划为准）、`apple`（以 Apple 为准）、`completion`（明确确认当前完成内容）或 `new`（明确新任务并保留旧任务）。输入 `YES` 后只执行获准内容；快照变化时拒绝。结果未知的待执行操作不能简单确认覆盖；需要核验，程序会暂停。

不要删除状态数据库、修改任务编号或删除并重建测试列表来“解决”同步问题，那可能破坏去重依据。

### F. 独立飞书测试表

只有 Apple 虚构测试通过后才执行：

- 建立**独立文件**和数据表，二者均命名 `CRM-SYNC-TEST`，只填虚构客户；不是在正式客户文件内加测试数据。
- 建立独立测试应用、只授权这个测试文件，申请测试用记录更新权限；正式应用继续只读，具体权限名届时按后台核实。
- 测试表字段：名字（文本）、下次follow（文本）、最新follow（文本）、跟进任务状态（单选）、跟进任务编号（文本）、跟进计划记录时间（日期时间）。状态选项至少包含 `进行中`、`已完成`。
- 一个虚构客户使用明确未来日期及行动；初始编号/状态留空。计划记录时间只用于日期基准，不自动用创建时间替代。
- 用配置工具输入测试标识和允许同步的虚构记录 ID：

```sh
python3 -B -m crm_sync.setup_feishu
```

然后：

```sh
python3 -B -m crm_sync.main feishu-test
```

App Secret 在终端隐藏输入，只存运行进程内存；不会保存到文件、命令参数或日志。这个测试模式不会读取 Codex 的正式 FEISHU_* 变量。每次启动重新输入测试应用密钥；自动登录启动和 Keychain 集成暂未实现。

连接器先核实测试文件/数据表名称、字段类型及记录白名单，只逐条读取白名单中的虚构记录，不列出正式客户数据。仅可更新下次follow、最新follow、跟进任务状态、跟进任务编号；计划记录时间在测试表手动维护，目前程序不会写它。

正式文件和测试文件若有人起相同名字，名称保护不足以判定真实性，因此独立应用的授权隔离必须由你在飞书确认。程序不能凭名称证明数据是虚构的。

后续分次测试创建、飞书改单、Apple 改期/内容、完成覆盖、同名虚构客户、两边同时修改、逾期、重新启动。`--watch` 和 `--review` 也可用于这个测试模式。

## 当前限制与下一轮

- macOS SDK、权限和 iCloud 集成必须本机验收；云端不能替你完成。
- 飞书写前读取不等于服务端原子条件更新；在正式生产开放前还要处理并发写入的最后间隙，测试阶段避免同时操作写入窗口。
- 模糊规则默认未批准。这里只支持已有解析器格式；缺少记录时间或歧义时暂停，不自动猜你想哪年。
- 暂未支持多任务/新轮次自动转换、重新打开完成任务、操作系统自动启动、密钥持久化、批量冲突 UI、正式客户权限或语音。
- 网络异常时安全停止，持久化状态可在重启后核对；未加入全套健康告警和生产恢复流程。
- 状态损坏或结果未知时暂停，不删除或重复创建来绕过问题。

这些限制不影响先进行指定的模拟与隔离实机测试，但不应把测试版当作已完成生产同步系统。
