# Apple 完成回写时间判断修复

2026-10-12 在用户的独立测试列表上，仅用只读诊断发现：两条任务的修改时间分别比完成时间晚约 0.784ms 和 2.590ms。原先 `modified <= completed` 的严格比较导致正常完成也暂停。

修复采用两层条件：

1. EventKit 的修改时间允许最多 10ms 的完成写入时间漂移；缺少任一时间仍不自动确认，差值大于 10ms 仍暂停。
2. 同步引擎要求任务当前内容及日期与上一条成功同步基线一致。如果改内容/日期后未先同步就勾选完成，即便时间接近也需确认最终快照。

这里的 10ms 是针对已观察系统行为的保守工程容差，不是 Apple 的官方保证，也不证明完整历史。如果完成后编辑导致更大差值，暂停；无法还原完成瞬间内容时继续人工确认，不用大容差掩盖未知情况。修改内容后先成功同步，再勾选完成，可按基线自动处理。

66 个模拟测试通过，包括正常未变内容自动完成、内容与完成同时变化暂停、缺少核验暂停、双方冲突及人工确认。Swift 时间条件在 Linux 无法编译执行；需用户更新桥接文件并在 Mac 编译，最终实机结果仍待验证。

此次没有读真实客户记录、修改飞书或 Apple 任务。已有任务编号、状态数据库、配置和密钥均保持不变。
