# 客户跟进模块规则

## 目标与现状
- 飞书是唯一正式客户数据库，任务工具用于提醒和更新跟进计划。
- 当前保留两条独立试验路径：
  A. 飞书多维表格 ↔ Apple 提醒事项。
  B. 飞书多维表格 ↔ 飞书任务。
- A 已有核心双向同步实机测试成果；B 已有创建、关联及单次更新测试成果。两者均未正式上线，不能互相套用测试结论。
- 最终路径尚未选定，不默认切换或同时启用两套正式执行器。语音功能继续暂停。

## 开始工作前
- 先读 README、docs/FINAL_SYNC_REQUIREMENTS.md 和最新交接记录，核对后续修订。
- 保留已有代码、任务关联和测试成果，不通过删除任务、清空 ID 或状态库排障。
- 代码存在不等于服务正在运行；分别核对代码、Mac 和云端的实际状态。

## 同步业务规则
- 飞书下次follow生成或更新对应跟进任务；每客户默认一个当前跟进任务。
- 任务改期或修改行动内容时，更新同一客户的下次follow，不改动无关字段。
- 任务完成时，按已确认映射回写实际完成时间和最终行动内容至最新follow，并清空对应的下次follow。
- 不编造客户回复、沟通结果或完成摘要；无法确定完成时内容或时间时暂停回写。
- 已明确的日期按授权规则处理；模糊或有歧义的日期不得擅自猜测。
- 旧任务完成不得覆盖后续新计划；逾期或暂时无法访问客户时，不自动删除任务。

## 关联与异常处理
- 使用记录 ID、任务 ID 和计划编号关联，不单靠客户姓名匹配。
- 重复运行不得重复建任务或形成循环回写。
- 双方同时修改且内容不同，展示冲突并由我选择，不默认按最后修改时间覆盖。
- 结果不明时先核验；保留原任务和待处理状态，避免盲目重试。
- Apple 与飞书任务路径分别保存关联和运行状态，不混用。

## 测试与上线
- 仅在批准的独立测试表和专用测试列表中进行写入测试；正式客户连接保持只读。
- 不扫描、上传或修改专用列表之外的个人提醒事项。
- 正式上线前，确认所选路径、字段权限、备份、暂停恢复及失败处理，并完成对应路径验收。
- Mac 依赖、云服务、同步频率和费用须明确说明；未验证前不承诺全天或实时同步。
